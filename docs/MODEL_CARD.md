# Model Card: Sentinel RUL Regressors

Two model tracks exist on purpose. The **serving model** is what the live loop and API deploy; the
**offline candidates** are evaluated on real data to decide what serving should become. All
figures come from [EVALUATION.md](EVALUATION.md), which is generated by `make report`.

## Serving model (`sentinel.model.RidgeModel`)

- **Task**: remaining useful life (cycles) from one telemetry row, capped at 125.
- **Inputs** (`sentinel.features.FEATURE_NAMES`, 9 values): cycle/150, operating setting 1,
  five sensors (C-MAPSS s2, s3, s4, s7, s11) and 5-cycle rolling means of two of them.
- **Algorithm**: closed-form ridge regression on standardized inputs (α = 0.5), NumPy only.
- **Training**: bootstrap on the reference domain; retrained on recent Gold rows when drift is
  detected. Validation holds out whole engines (`group_split`); `holdout_mae` is recorded in the
  registry alongside the in-sample `training_mae`.
- **Release gate**: offline gate (candidate validation MAE within 5% of production), then a
  shadow canary promoted only by a paired non-inferiority test (95% bound within a 3% margin).
- **Real-data quality**: experiment `serving_ridge` — see the table in EVALUATION.md §1.

## Offline candidates (`sentinel.evaluation`)

| Experiment | Features | Model |
| :--- | :--- | :--- |
| `mean_baseline` | – | training-mean RUL |
| `serving_ridge_uncapped` | serving 9 | ridge, raw RUL (status quo before calibration) |
| `serving_ridge` | serving 9 | ridge, RUL ≤ 125 |
| `offline_ridge` | informative sensors, per-regime z-score, 30-cycle rolling mean/slope/std | ridge |
| `offline_quadratic_ridge` | same | ridge on features + squares |
| `offline_rff_ridge` | same | RBF kernel ridge via 600 random Fourier features |

Hyperparameters are selected by 5-fold engine-grouped CV on the training file only; the official
test file is scored once at each engine's last cycle.

## Intended use and limitations

- Reference implementation for MLOps release mechanics on simulated data, not an airworthiness
  tool. Do not use predictions for maintenance decisions.
- Linear serving model under-fits the knee of the degradation curve; FD002/FD004 need per-regime
  normalization that the 9-feature contract does not have.
- RFF candidate quality varies slightly with the random feature seed (reported as ± std).
- Error is asymmetric in cost: the NASA score penalizes late (over-estimated RUL) predictions
  more; both RMSE and NASA score are reported.
